Tools service

Status: current for c-330 (connections and the one executor), c-331 (MCP sign-in), c-332 (mock answers) and c-356 (the MCP server, slice 1: a team's reads over MCP with an API key). The tools service is the one way out for tool calls: a call resolves through the registry, passes the gateway's checks, signs in through its module's connection for the run's environment, and goes out through the egress client. Full product design: the tools system design in the planning notes, outside this repo.

Sequences

A call that refreshes a token

  1. agents-service: POST /v1/calls, environment: production
  2. Gateway checks pass; Authenticator.prepare reads the connection and its production row
  3. Tokens.access: read the token; inside 60 s of expiry, POST the token address with the refresh token (egress client, no lock held); store the new tokens against the rotation read, or read the winner's
  4. Send with Authorization: Bearer; on 401 for a read, step 3 again for that token only, then send once more
  5. Scrub every token and secret value from the answer; log environment and connection

Signing in once with the team's account

  1. Console: POST …/sign-in {environment}; the service checks the sign-in address is on the allow-list, stores the state hash and the encrypted PKCE verifier for ten minutes
  2. The browser goes to authorizeUrl; the person signs in; the system sends the browser to the console's return page with code and state
  3. Console: POST …/sign-in/complete {state, code} under the same person's token; the state is taken once
  4. The service exchanges the code with the verifier through the egress client and stores the tokens; status working; activity names the account

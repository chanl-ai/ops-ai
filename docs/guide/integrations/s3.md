# Amazon S3

Status: current. Ships with Ops AI; a team admin turns it on.

Invoices, claims and statements often land as files in an S3 bucket that another system writes to. The Amazon S3 app
reads those buckets, or any store that answers the S3 API (MinIO, SeaweedFS, Cloudflare R2, Wasabi), so a knowledge
base or a watched folder stays current with them without anyone copying files into Ops AI.

## Turn it on and add a source

<!-- site: steps -->
1. **Turn on.** A team admin opens **Data Gateway › Apps**, finds Amazon S3, and presses **Turn on**. Enter the S3
   address: `https://s3.<region>.amazonaws.com` for AWS, or your store's address. The address is path style, so the
   key is only ever sent to that one host.
2. **Connect the team account** with an access key ID, its secret access key and the region. An address on a host
   your security team has not listed is held until they list it, and nothing is sent to it before then.
3. **Test the connection.** **Test** signs a request with the key, as every call is signed. A wrong secret says
   "S3 refused the access key: the key or its secret is wrong."
4. **Add a source or watch a folder.** In **Knowledge**, press **Add source** and pick Amazon S3; in **Files**, press
   **Watch a folder**. Search for buckets, open one to pick a folder under it.

The same source from the command line:

```bash
opsai kb scopes --plugin opsai.s3 --source files --query "claims"             # find the bucket
opsai kb add-source "Claims" --kb kb_... --plugin opsai.s3 --source files --value folders=claims-archive/2026/
opsai kb sync kb_...
```

Expected: the folder's files are listed as indexed.

## What it brings

| Kind | What |
|---|---|
| Knowledge source | Files under the picked buckets and folders. S3 has no change feed, so each sync lists the folder whole; a file whose version tag (ETag) did not change is not fetched again, and a file no longer listed is marked removed |
| Read tools | List files, read one file, find buckets and folders, preview what a source would take in |

A file moved or renamed in S3 is a new key. When exactly one removed file and exactly one new file in a check hold
the same bytes, the new file's page says **Was** with its old path; two copies of the same bytes link nothing.

## Source options

| Option | What it does | Default |
|---|---|---|
| Folders | Buckets or folders to take in, each as `bucket/prefix` | None |
| Schedule | When the source syncs | Daily at 02:00 |

## What the key needs

| S3 permission | Why |
|---|---|
| `s3:ListAllMyBuckets` | Find buckets when picking |
| `s3:ListBucket` | List the picked folders |
| `s3:GetObject` | Read the files |

Ops AI only reads. It never writes to the bucket.

## Limits

- One team account per connection, signed with an access key. Temporary credentials and assumed roles are not offered.
- Files larger than 25 MB are listed as failed and not fetched.
- A file is readable through the team key's access, not each reader's. Put only what the whole team may read in the
  source.

# Docs site: working rules

Status: current.

This app is a Fumadocs site on Next.js 16, served under `/docs`, that renders `docs/` and each
`services/*/openapi.json` as they are in the repository; it holds no copy of the content. Read the Next.js version notes
in @AGENTS.md before writing Next.js code. How to run it: [README.md](README.md). Rules shared with every folder:
[Working in one folder](../../CLAUDE.md#working-in-one-folder).

## What it owns

| Path | Holds |
|---|---|
| `src/lib/nav.mjs` | `SITE`: the four tabs (Docs, API reference, Architecture, Contributing), their groups and entries. A page under `docs/` that `SITE` does not place fails the build |
| `src/lib/remark-ops-ai.mjs`, `src/components/` | The markdown conventions mapped onto components: status badges, summary cards, steps, callouts, mermaid, box diagrams, figures, file links |
| `src/lib/repo.mjs` | Reading the repository: the repo root, the docs index, file links to GitHub |
| `src/app/` | The catch-all page route, search, and `files/[...path]` for linked repository files |
| `scripts/check-links.mjs` | Every link resolves and every page sits in a tab |
| `scripts/export-diagrams.mjs` | `docs/diagrams/<name>.yaml` exported to its SVG; `--check` fails on a stale SVG |
| `vercel.json` | Static hosting under `/docs` ([docs/deploy/docs-site.md](../../docs/deploy/docs-site.md)) |

## Run and check from this folder

| Task | Command (in `apps/docs/`) |
|---|---|
| Link and tab check (seconds) | `pnpm check:links` |
| Diagram SVGs current | `node scripts/export-diagrams.mjs --check`; `pnpm diagrams` rewrites them after a `.yaml` edit |
| Local site | `pnpm dev` → http://localhost:3040/docs |
| Static export to `out/` | `pnpm build` (runs the link and diagram checks first) |
| Type-check | `pnpm typecheck`, which fails on a clean checkout: the `fumadocs-mdx:collections/server` module and the SVG module types are generated by `pnpm dev` or `pnpm build`, so run one of them first |

Nothing in `make verify` runs this app; `pnpm build` is its gate. A change to a page under `docs/` is checked by
`make docs-verify` from the root (placement, status line, index) and by `pnpm check:links` here (links and tabs).

## Writing for the site

The markdown conventions the site understands (status line, badges, `<!-- site: cards -->`, `<!-- site: steps -->`,
alerts, mermaid, diagrams, figures, file links) are listed once in
[docs/README.md, "How the docs site shows a page"](../../docs/README.md#how-the-docs-site-shows-a-page). A new page is
listed in `docs/README.md` and placed in `SITE`; the page's opening paragraph stays free of paths and code spans
(`CONTRIBUTING.md`, writing rules).
